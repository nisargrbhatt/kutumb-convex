## 5. Drizzle migrations

Stripe schema lives only in `migrations/0002_icy_blue_blade.sql`: `CREATE TABLE subscription`
(:1-19), index (:21), `ALTER TABLE organization ADD stripe_customer_id` (:22),
`ALTER TABLE user ADD stripe_customer_id` (:23). **But** the same file (:24-44) also rebuilds
`session` with FK cascades (`user_id` → cascade, `active_organization_id` → set null) — that part is
unrelated to Stripe and must survive. `migrations/meta/0002_snapshot.json` references `subscription`
too.

**Recommend: forward migration, not reset.** Edit `auth-schema.ts`, run `npm run migration:generate`
→ `0003_*.sql` (drizzle-kit sqlite will emit `DROP TABLE subscription` and table-recreate for the
two column drops). Works whether or not the DB is cleared, keeps 0002's session-FK change, and keeps
`_journal.json` linear. Rewriting/deleting 0002 would require hand-splitting the session rebuild and
a full D1 reset (`wrangler d1 migrations apply` tracks applied tags in `d1_migrations`). Reset only
buys avoiding one migration file; not worth it.
